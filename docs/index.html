strawmANN

A deliberately unfair strawman for approximate nearest neighbour search

A Qdrant-wire-compatible vector engine in Zig, built as a performance oracle: no compatibility debt, no distribution, no product. These are its benchmark runs against Qdrant 1.19.

Run reports

Each page is one full benchmark run, self-contained and needing no network. It states its own licence in the header: the gate verdict per arm, the conformance tier and hash, the environment hash, the pass count, and a banner on every row the comparison refuses. Read that before quoting a number off it.

sift1m, measured 2026-09-25 20:21 currentT4gate pass3 passes

sm-sift-perf-0926 vs qd-sift-perf-0926

At equal recall, strawmANN serves 1.78x to 2.14x Qdrant's throughput. That range spans the recall levels measured; allowing for the uncertainty in each recall figure widens it to 1.28x to 3.29x.

dbpedia-openai-1m, measured 2026-09-24 21:52 currentT4gate pass3 passes

sm-dbp1m-perf-0925 vs qd-dbp1m-perf-0925

At equal recall, strawmANN serves 1.26x to 1.44x Qdrant's throughput. That range spans the recall levels measured; allowing for the uncertainty in each recall figure widens it to 1.03x to 1.55x.

The pages are not a series. Each is one run, and when the harness configuration changes between runs compare.py refuses ratios across them as STALE. Read each page against itself. Superseded pages are retired to the repository's git history.

Disclosure: the author works at Qdrant, on the engine being measured. Nothing here is a Qdrant position and nobody at Qdrant has reviewed it.
